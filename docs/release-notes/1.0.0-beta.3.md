# QueryMole 1.0.0-beta.3

**QueryMole** is a revival of the classic MySQL Query Browser: the original Windows user interface, unchanged,
rebuilt with Free Pascal and Lazarus for current MySQL (5.7 to 9) and MariaDB (10.11, 11.4), on Windows and Linux.

**The third beta of 1.0.0.** Everything the original does works, and the features for 1.0.0 are complete: from now
on until 1.0.0 only faults are fixed (ADR-0055). Please try it in your daily work and report what goes wrong. Use a
test account or a test server for anything important and keep your own backups. QueryMole is not affiliated with
Oracle; "MySQL" is a trademark of Oracle.

New in this release (fixes since 1.0.0-beta.2):

- **Windows: "Cancel" in the connect dialog at start** ended the program with "Das Handle ist ungültig" (OS error 6)
  instead of opening it without a connection. The program now ignores a failure to register itself in the list of
  running instances (it only feeds the Window menu). If it still ends, `querymole.error.txt` and, with the
  environment variable `QBR_TRACE=1`, `qbr.trace.txt` next to the program show where; please send them.

The fixes of 1.0.0-beta.2 (also in this release): emoji and other 4-byte characters (the connection uses `utf8mb4`,
ADR-0056), large results load much faster, the export is disabled while rows are still loading, empty BLOB values are
empty and not NULL, and the table editor keeps expression defaults and defaults with a quote in them.

## Updates

**Help > Check for Updates ...** in 1.0.0-beta.2, in 1.0.0-beta.1, in 0.1.0-alpha.9 (or an earlier alpha from alpha.5 on) finds this release, downloads
and installs it, then restarts the program; your settings and stored connections stay as they are. It works in the
Windows installation and in `QueryMole.AppImage`; in the portable zip and in the AppImage without updater the entry
is disabled.

Which versions are offered: betas and release candidates of 1.0.0 are offered to this beta; once you run 1.0.0, only
releases are offered, unless you tick "Offer development versions (alpha, beta)" in the update dialog.

## Changes since 0.1.0-alpha.9

(The fixes of the betas are listed at the top; the following was already in 1.0.0-beta.1.)

- **Start without a connection** (ADR-0052): "Cancel" (and the hidden "Skip") in the connect dialog at start open the
  main window without a connection instead of ending the program. The menu entry File > Reconnect reads "Connect"
  then; the parts of the window that need a server stay empty until you connect, and functions that need one say
  so.
- **Automatic update check** (ADR-0052), off by default: at the first start the program asks once whether it may
  look for updates at start. The setting is in Options > Browser ("Check for updates at start") and in the update
  dialogs, which also have "Offer development versions (alpha, beta)". When it is on, the program checks in the
  background and is silent unless there is a newer version; then it asks as Help > Check for Updates does. Nothing is
  downloaded without your answer, and errors of the automatic check are not shown.
- **Connect dialog** (ADR-0052, ADR-0053): the QueryMole icon in the banner is animated while connecting. The "Stored
  Connection" list shows the group in front of each name and follows the order of the connection manager's tree;
  the stored name never takes the group.
- **SSH tunnel** (ADR-0053): the SSH Tunnel dialog has a password field next to "Password:". The password is stored
  as the connection's password is (Options > General: plain text, obscured, or on Windows with the operating
  system), or not at all; left empty, it is asked for when connecting, as before. A password typed at that question
  is used for the rest of the session before the stored one.
- **Linux:** the GTK2 version, kept buildable since the switch to Qt 6 in alpha.6, has been removed; the AppImages
  are the same Qt 6 build as before.

## What works

Connecting (TLS "preferred" with fallback, SSH tunnel), stored connections in groups with a "Test" button, the
schema tree, the SQL editor with highlighting, running queries, the result grid with editing, several result tabs,
EXPLAIN, scripts with breakpoints, export to CSV, TSV, JSON, JSON Lines, HTML, XML, Excel and PLIST, the help panel
(the reference comes from the connected server), the table editor, options, text search, the regular expression
importer and updates. An automated suite runs against MySQL 5.7, 8.0, 8.4, 9 and MariaDB 10.11 and 11.4 on every
change.

## Known problems

- **Linux on Wayland:** started from a terminal, the program prints messages from the Qt toolkit about combo boxes
  and mouse grabbing; they are harmless. If dragging (splitters, column widths, drag and drop) misbehaves, start it
  with `QT_QPA_PLATFORM=xcb` (it then runs through XWayland) and tell us.
- As in the original, every row of a result is kept in memory (about 1 KB per row): for very large results add a
  `LIMIT`. A pause-and-ask guard against running out of memory is planned for 1.1.0 (ADR-0057).
- **Tried less than the rest, so especially worth testing:** on Windows the SSH tunnel with Pageant and with PuTTY
  keys; on both platforms the connection manager's context menu and drag and drop into groups, the update question
  at the first start, and real mouse and keyboard use with bookmarks, history and the field viewer.
- **SSH tunnel:** key passphrases are not stored, only asked for. An earlier release opening a connection with SSH
  settings connects directly to the server host (often `127.0.0.1`) and may reach a different server. A stored SSH
  password is kept by 0.1.0-alpha.8 and alpha.9 as it is; if you change the password storage type in one of them,
  the stored SSH password is asked for again.
- An empty group of connections is not kept.
- The table editor keeps generated columns, `ON UPDATE`, `INVISIBLE` and CHECK constraints when it changes a table,
  but does not show or edit them yet (ADR-0035).
